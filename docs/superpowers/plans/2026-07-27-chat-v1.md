# Chat (v1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1 student↔student chat — 1:1 conversations gated by an accepted connection, real-time over Socket.IO, with delivery/read receipts, typing, online + last-seen presence, unread counts, a conversation list and paginated history.

**Architecture:** New feature module `src/modules/chat/` (DDD four layers). Messages persist in Postgres with a per-conversation monotonic `seq`; presence lives in Redis. The WebSocket gateway is a `presentation` adapter; a REST surface mirrors it for history/list and as a send fallback. Chat depends on an accepted connection via a small `ConnectionCheck` port (reads the `connections` table — no coupling to the connections module's internals). **Plan 2 of 2** — builds on Plan 1 (Connections).

**Tech Stack:** NestJS + `@nestjs/websockets` + `@nestjs/platform-socket.io` + `socket.io` + `@socket.io/redis-adapter`, Prisma/PostgreSQL, `ioredis` (existing `RedisService`), class-validator, Jest.

**Spec:** `docs/architecture/chat.md` — decisions C2 (Socket.IO), C3 (unified Conversation), C4 (per-conversation `seq`), C5 (per-member cursors), C6 (WS + REST + `clientMsgId`), C7 (presence), C9 (disconnect keeps history).

**Preconditions / gaps:** Plan 1 must be migrated first (`connections`/`blocks`/`reports` + `students.username` in the DB). Neither plan has been booted against a real DB yet — **Task 8 (boot + e2e) is the first runtime verification of both plans; do not skip it.** `git commit` is denied to the agent — commit checkpoints are the owner's.

**Conventions:** Full code for schema, the `seq`-assignment transaction, the gateway auth + Redis adapter, and the delivery/read logic (the non-obvious parts). Boilerplate that mirrors an existing file (DTO envelopes, mappers, Prisma repos) is specified by reference to that file. Out of scope (v2/v3): media, reply, edit, delete, reactions, search, pin, groups.

- [ ] **Step 1: `chat.mapper.ts`** — `toMessage(row)`, `toConversation(row)`, `toMember(row)`; and reuse `ConnectionMapper.toSummary` shape for the other member (select `id, username, firstName, lastName, avatarUrl`).

- [ ] **Step 2: `chat.prisma.repository.ts`** implementing `ChatRepository`. The **critical** method — atomic seq:
```ts
async appendMessage(conversationId: string, senderId: string, body: string): Promise<Message> {
  const row = await this.prisma.$transaction(async (tx) => {
    // Post-increment: the returned nextSeq is the NEW value; this message takes nextSeq - 1.
    const convo = await tx.conversation.update({
      where: { id: conversationId },
      data: { nextSeq: { increment: 1 }, lastMessageAt: new Date() },
      select: { nextSeq: true },
    });
    return tx.message.create({
      data: { conversationId, senderId, seq: convo.nextSeq - 1, body, type: PrismaMessageType.TEXT },
    });
  });
  return ChatMapper.toMessage(row);
}
```
  - `findDirect`/`createDirect` use `directKey`. `createDirect` nested-creates the two `ConversationMember` rows.
  - `listMessages`: `where { conversationId, seq: beforeSeq ? { lt: beforeSeq } : undefined }`, `orderBy seq desc`, `take size`.
  - `listConversations`: members where `studentId`, include conversation + its other member + the top message; `unreadCount` = `message.count({ where: { conversationId, seq: { gt: lastReadSeq }, senderId: { not: studentId } } })` per row (page-bounded N+1, acceptable v1); order by `conversation.lastMessageAt desc`.
  - `advanceCursor`: `updateMany({ where: { conversationId, studentId, [col]: { lt: seq } }, data: { [col]: seq } })` — monotonic (never backwards).

- [ ] **Step 3: `connection-check.prisma.repository.ts`** — `areConnected(a,b)`:
```ts
const [edge, block] = await this.prisma.$transaction([
  this.prisma.connection.count({ where: { status: 'ACCEPTED', OR: [ {requesterId:a,addresseeId:b}, {requesterId:b,addresseeId:a} ] } }),
  this.prisma.block.count({ where: { OR: [ {blockerId:a,blockedId:b}, {blockerId:b,blockedId:a} ] } }),
]);
return edge > 0 && block === 0;
```

```ts
async sendMessage(user, conversationId, body): Promise<Message> {
  const text = body.trim();
  if (text.length === 0) throw new AppException(ERROR_CODE.MESSAGE_EMPTY, 422, 'Xabar bo‘sh');
  const membership = await this.chat.findMembership(conversationId, user.id);
  if (membership === null) throw AppException.notFound(ERROR_CODE.CONVERSATION_NOT_FOUND, 'Suhbat topilmadi');
  const otherId = await this.chat.otherMemberId(conversationId, user.id);
  if (otherId !== null && !(await this.connectionCheck.areConnected(user.id, otherId))) {
    throw new AppException(ERROR_CODE.NOT_CONNECTED, 403, 'Avval bog‘lanish kerak');
  }
  return this.chat.appendMessage(conversationId, user.id, text);
}
```
`openDirect` guards self + `areConnected`, computes `directKeyOf`, `findDirect` ?? `createDirect`. `history`/`markRead` assert membership then delegate. **ChatService returns domain data only** — the gateway/controller handle broadcasting + DTOs.

## Task 6: WebSocket gateway + Redis adapter

**Files:** `chat.gateway.ts`, `chat-events.ts`, `src/main.ts` (Redis IoAdapter).

- [ ] **Step 1: `chat-events.ts`** — string constants + payload types for every event in chat.md (`message:send`, `message:read`, `message:delivered`, `typing:start|stop`; server: `message:new`, `message:delivered`, `message:read`, `typing`, `presence:update`).

- [ ] **Step 2: `chat.gateway.ts`** — `@WebSocketGateway({ namespace: '/chat', cors: false })`:
  - `handleConnection(client)`: verify `client.handshake.auth.token` via `ws-jwt`; on failure `client.disconnect()`. Store `studentId` on the socket. `presence.online()`; join a room per conversation the student belongs to (and a personal room `user:{id}`); broadcast `presence:update {online:true}` to the student's connections.
  - `handleDisconnect(client)`: `presence.offline()`; if truly offline, persist `lastSeenAt` + broadcast `presence:update {online:false, lastSeenAt}`.
  - `@SubscribeMessage('message:send')`: call `ChatService.sendMessage`; **ack** the sender `{clientMsgId, id, seq, createdAt, status:'sent'}`; `server.to(room).emit('message:new', …)`.
  - `message:read` / `message:delivered`: `advanceCursor` then emit the receipt to the other member.
  - `typing:start|stop`: broadcast `typing` to the conversation room (no persistence).
  - Idempotency: keep a short-lived `clientMsgId`→messageId cache (Redis, TTL) so a retried send returns the same ack instead of duplicating (C6).

- [ ] **Step 3: Redis adapter in `main.ts`** — a custom `IoAdapter`:
```ts
class RedisIoAdapter extends IoAdapter {
  constructor(app, private pub: Redis, private sub: Redis) { super(app); }
  createIOServer(port, options) {
    const server = super.createIOServer(port, options);
    server.adapter(createAdapter(this.pub, this.sub));
    return server;
  }
}
// in bootstrap(): app.useWebSocketAdapter(new RedisIoAdapter(app, pub, sub)) using two ioredis clients.
```
So `message:new` fans out across instances (chat.md C2 scaling).
